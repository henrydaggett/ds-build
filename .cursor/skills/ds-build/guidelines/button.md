# DsButton guidelines

## When to use

- Use a DsButton for an action: save, submit, create, delete, continue.
- Don't use a DsButton for navigation to another page.
- Don't use a DsButton for an on/off setting; use a DsToggle.

## Variants

- Use one primary (default) button per section for the main action.
- Use outline for secondary actions like Cancel or Back.
- Use red only for destructive actions the user asks for, like deleting data.
- Use blue only when the user asks for an accent or call to action.

## Content

- Keep labels short: one to three words.
- Start labels with a verb: "Save changes", "Create project".
- Use sentence case: "Add member", not "Add Member".
- Don't end labels with punctuation.

## Layout

- Place related buttons side by side, primary first.
- In a form, put buttons in DsFormActions at the end.
- Use the same size for buttons that sit next to each other.
- Only add an icon when it makes the action clearer.
